V4–V13 각각의 완료 보고서와 unresolved 목록이 있어야 한다. 기능 이름만 존재하는 항목은 완료가 아니다.

1. 저장소 루트에서 git status와 이전 버전 완료 보고서를 읽는다. 미커밋 사용자 변경을 보존한다.
2. 이전 보고서의 자동 검증/real backend/GUI 검증을 따로 확인한다. 실패를 무시하고 진행하지 않는다.
3. 아래 신규 파일은 설계 후보다. 같은 책임의 파일이 이미 있으면 그것을 확장하고 중복 구현하지 않는다.
4. API는 현재 설치 source로 확인한다. 아래 타입명은 새 계약 제안이며 이미 존재하는 심볼로 가정하지 않는다.

## 4. 데이터 계약 — UI보다 먼저 정의

공통 envelope의 session/epoch/seq/tick과 simulation-owner 규칙을 유지한다. 필수 값 누락/NaN/잘못된 배열 길이는 실패해야 한다. optional telemetry와 필수 control 필드의 허용 정책을 구분한다.

### AcceptanceMatrix

requirement_id, version, implementing files, test command/exit/log, GUI action evidence, status, limitation.

### ReleaseManifest

git SHA/dirty state, runtime/dependency versions, dataset/license hashes, schemas, supported effects, module API version, test artifact hashes.

### FinalStatus

verified / partial / unsupported / failed. 구현 성공·동물과의 동등성·게임 모듈 제공을 구분.

### Delivery

실행 경로, 사용자 가이드, sample world, 저장 위치/복구 방법, 전체 요구 잔여 목록.

## 5. 구현 순서 — 위에서 아래로 실행

각 단계는 해당 출력과 검사 증거를 만든 후 다음 단계로 넘어간다. 전체 파일을 한 번에 새로 쓰는 방식은 피한다.

### 14.1. 요구 추적표 채우기

**할 일:** 원래 사용자 요구 네 가지: 세계 안 참여, 모든 환경 제어, 욕구/정서/각성 활동 표시, 외부 I/O 장착 기반을 각각 세부 행으로 나눈다.

**완료 출력:** 빠진 요구나 placeholder를 찾음.

**다음 단계 진입 조건:** 이 출력의 정상 사례와 실패/무변경 사례를 확인하고 진행표의 `V14.1` 행에 증거를 남긴다. 검사 실패 시 같은 단계에서 원인을 수정한다.

### 14.2. fresh 실행 검증

**할 일:** 현재 launcher로 새 앱/실제 backend를 시작한다. 과거 프로세스·오래된 바이너리 성공을 재사용하지 않는다.

**완료 출력:** build hash/실행 프로세스/연결 상태 증거.

**다음 단계 진입 조건:** 이 출력의 정상 사례와 실패/무변경 사례를 확인하고 진행표의 `V14.2` 행에 증거를 남긴다. 검사 실패 시 같은 단계에서 원인을 수정한다.

## 6. 실패·취소·복구

V14는 미완료 기능을 발표 문구로 덮는 단계가 아니다. 핵심 요구가 남으면 partial로 기록하고 해당 버전의 보완 작업을 먼저 마친다. 연구적으로 미검증인 항목은 그 사실과 남은 목표를 함께 전달한다.

공통 규칙: 실패한 명령은 applied로 표시하지 않는다. 이전 정상 파일/세션을 먼저 삭제하지 않는다. timeout은 무한 재시도로 숨기지 않는다. UI는 오류 원인과 재시도 가능한 작업을 보여준다. queue drain/ACK가 완료되지 않으면 saved/paused/detached 성공을 추정하지 않는다.

## 7. 이번 버전에서 만들지 않는 것

출시 직전 새 엔진 교체/전신 connectome 교체/실제 게임 모듈 제작은 하지 않는다.

## 8. 검증 시나리오 — 실행과 예상 결과

| ID | 실행 방법 | 합격 조건 |
|---|---|
| V14-01 최종 동선 | 공통 설계 §11의 10단계를 새 프로세스에서 수행. | 각 단계 자동+GUI 증거, 실제 backend 사용. |
| V14-02 독립 재개 | 앱 완전 종료 후 저장 세션 열기. | identity/state/환경/해석/시간축 보존. |
| V14-03 의도적 실패 | 손상 world/모듈 timeout/저장 실패 fixture. | 정상 상태 보존, 명확한 실패/복구. |
| V14-04 요구 정합 | 요구 추적표와 UI/소스/로그 대조. | unsupported를 implemented로 둔 행 없음. |
| V14-05 최종 범위 | 실제 게임 adapter와 근거 없는 emotion 값 검색/목록 확인. | 게임 모듈 미제작, 추정/관측 구분 유지. |

검사 코드는 이 표의 동작과 실패 조건을 검증해야 한다. 구현의 상수를 복사하여 항상 통과하는 테스트를 만들지 않는다. 실행 명령은 공통 playbook에 따라 구현 후 실제 존재하는 test entry를 기록한다. 아직 만들지 않은 테스트 명령을 이미 실행 가능한 것으로 보고하지 않는다.
